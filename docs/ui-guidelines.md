# got-it UI 规范

维护日期：2026-10-20。适用范围：阅读器应用控件、工具栏、弹层、导航和知识贴；不覆盖导入文章自身的图片、配色和排版语义。

## 1. 产品原则

- **正文优先。** 工具服务阅读，常用操作紧凑同排；状态与说明不无故另占一行。必要时换行保证可读与可点击，不以压缩热区换取密度。
- **操作直观。** 同一个动作只保留一个清楚的入口；图标表达动作，提示说明结果。主操作、次操作、危险操作有层级。
- **状态真实。** 持续选中不等于鼠标按住；禁用不等于失败；已保存必须对应真实保存成功。非核心元信息按需显示。
- **主动权属于读者。** 切换文件或展开面板不隐式发起 AI 请求；颜色不能替代错误说明或必要授权。

功能行为与数据边界以项目约定和相关功能规格为准。这份文档不新增授权或修改功能范围。

## 3. 颜色与操作层级

- 普通控件默认保持中性；hover 使用小面积主题浅紫。持续选择与视图切换采用纸面选中底、蓝紫文字和完整描边，选中 hover 保持纸面；pressed 使用细内描边，focus-visible 使用带间隔的外轮廓，两者分别表示按住和键盘定位。主操作/危险/禁用保持独立语义。
- 主操作采用实心主题色，例如明确提交、阅读文章；一组动作中避免所有按钮都同等突出。
- 次操作可用描边或透明底；相同用途在相同上下文中采用相同表现。
- 危险确认保留红色语义；警告、错误、成功状态可保留语义色，不强行统一成紫色。
- Disabled 使用共享禁用变量，不靠降低整体透明度造成文字和边框难以辨认。
- 文章原图不染色；图片放大入口只改变轮廓。遮罩与正文/回答中的原始 HTML 不套用应用按钮规则。

普通小字号文字以至少 4.5:1 对比度为验收目标；非文本图标与必要边界以至少 3:1 为目标。禁用控件单独评估，不把禁用样式当成可操作状态。不能只检查默认态，选中后按下、危险确认按下也要检查。

## 4. 状态规则

| 状态 | 意义 | 规则 |
| --- | --- | --- |
| default / normal | 没有交互 | 体现主次层级，不冒充选中 |
| hover | 指针悬停 | 可交互控件有主题反馈；仅在支持 hover 的设备应用 |
| active / pressed | 正在按住 | 短暂反馈；释放后恢复，不能代表持续模式 |
| disabled | 当前不可操作 | 原生 button 优先使用 `disabled`；鼠标和键盘均不能执行，hover 不恢复可用外观 |
| selected / current | 当前模式或条目 | 用正确的 `aria-pressed`、`aria-selected`、`aria-current`；与 hover 和 pressed 能区分 |
| expanded | 菜单或面板展开 | 用 `aria-expanded`；展开不等于业务选中 |
| focus-visible | 键盘定位 | 使用共享主题轮廓，不移除；不得被父容器裁切 |

`aria-disabled` 本身不会阻止事件，使用它时必须另行保证禁用行为。只读内容不能为了变灰就伪装成 disabled 按钮。

每个按钮检查四态，业务不存在的状态标为“不适用”，不为补齐展示而新增禁用条件。共享过渡遵从减少动态效果偏好。

## 5. 尺寸、间距与对齐

- 方形/矩形操作复用 `--control-radius`、`--control-font-size`；圆形发送按钮、文字入口、标签保留有意义的形状差异，不要求所有控件长得一样。
- 图标大小与点击区域分开：小图标可以保持精简，热区不能只剩图标本身。新控件默认至少24×24px可点击区域，触控优先44×44px；文字内联入口等例外须检查间距和可用性。
- 对现有小控件，优先用布局空间或透明热区扩大点击范围；检查相邻热区重叠、层级、遮挡、滚动裁切。扩大控件后同步检查父网格列，不能留下固定窄列。
- 当前选区关闭和PDF标记的具体桌面尺寸、触控规则见共享样式，避免文档数值落后。
- 工具栏与同一行的按钮保持视觉中心、边缘和分割线对齐。弹层上下留白平衡；状态说明尽可能紧邻关联动作。
- 分类、同锚点结果、Provider 选项、当前材料、Markdown/PDF 目录、左右固定按钮、收藏视图、原译文/PDF 框选复用共享持续选择规则。菜单仍用 expanded 语义；分类删除模式用切换反馈，真正确认删除保留红色。当前材料仅文件按钮着色，不把整行与路径染成连续色块。
- 分类控件四周留白8px、间距8px、8px独立圆角，始终预留1px边框，不再叠加底部选中线。默认360px知识贴显示“解释／来源／问题”短名称，必要隐藏计数，极窄才仅图标；现有220–720px宽度边界、99+数量规则、完整辅助名、title、busy与方向键/Home/End不变。密度沿用带滞回的面板实际宽度测量，不能用视口宽度代替。
- hover/selected/pressed不改变几何尺寸，首尾分类和固定按钮的焦点外圈不得被裁切。
- 先复用相邻组件的间距和现有断点。当前尚未将全项目间距统一成 token，不把“计划中的 token”写成已实施。
- 窄屏允许必要重排，但不能横向挤出、文字竖排或把重要操作藏到不可到达的位置。

## 6. 图标、文案与可访问性

- 优先沿用项目的 Lucide 图标；相同动作不混用不同符号表达。
- 已固定图钉实心，未固定描边；两者均保留正确可访问名称。
- PDF 知识贴使用批注图标与“查看知识贴”提示，避免外链式箭头造成误解。
- 纯图标按钮提供可访问名称；含义不明显时有可见说明或 hover 提示。`title` 可作补充，不能代替可访问名称，也不能作为触屏唯一说明。
- 图标旁已有完整文字时，装饰图标对读屏隐藏；删除/移出使用固定方形两步确认：首次改实心垃圾桶与红色圆角底，短抖一次；再次点击执行。辅助名称和 title 明确“确认删除”或“确认移出”，不以文字扩宽行；移焦/Escape/切换取消，减少动态偏好不抖动。
- 动作文案用清楚的动词与对象，状态文案描述当前事实；避免同一行重复“已保存”等信息。
- 颜色不作为唯一状态线索；选中、失败、禁用原因按场景用图形、文字或语义补充。

## 7. HTML 展示页维护

在仓库根目录运行：

```bash
node scripts/generate-button-showcase.mjs
```

生成到上表链接的HTML，下载HTML后可用浏览器离线打开；GitHub文件页本身不会运行HTML。共享CSS直接内嵌，重新生成后才能反映最新样式；生成器是[generate-button-showcase.mjs](../scripts/generate-button-showcase.mjs)。

当前限制：样例结构手写，容器为了横向对比而隔离排布；126个样例不是自动发现的全部控件清单。它可以发现状态颜色、内容和图标问题，不能证明真实布局、业务禁用条件或全部交互通过。

维护要求：

1. 控件文案、图标或结构变化时，同步对应样例；必须核对实际组件，不能凭印象复制。
2. 新增控件时加入或明确复用哪种样例；持续选中另列，不混入 pressed。
3. 示例只用安全内容，不带真实阅读库、账户或路径；点击不执行业务动作。
4. 收藏与理解操作共用同一浮窗底板，顶部选区预览横跨底板；收藏位于最左独立窄区，32px平面圆角方形（共享8px角，44px安全点击区）、紫色纯图标、留白和短竖分隔线，无阴影、凸起、特殊填充或悬停位移，普通三操作态关闭位于最右侧；进入选区“问一问”输入态后移除返回与叉号，仅保留输入和发送。点击浮窗外空白关闭选区，Esc关闭整个选区浮窗；内部点击、选择文字及提交不触发外部关闭，IME/Enter/Shift+Enter规则保持。普通结果返回、非选区追问与取消保持。有效跨段文字可独立收藏，也可完整发起理解请求；容量不足明确拒绝，不截断选区。提交成功后收起本次选区，以轻量下划线和读屏播报表示已保存，不弹成功提示或自动打开列表。Codex 选择器左侧放32×32px方形纯Bookmark图标入口，与Codex等高，使用共享圆角，默认紫色18px图标与44px透明触控热区，可访问名称/title与expanded保留，数量只在弹层标题显示，侧栏底部放「全部收藏」，默认Bookmark图标同紫色、文字中性，交互与禁用沿共享状态；全部卡片不展示原文版本编号，底层版本定位保留，本文版本元信息不变。本文popover用3行省略摘要；全部收藏直接显示完整摘录和明确标注的前后文，摘录不重复、不折叠。删除入口复用知识贴Trash2及两步确认，确认提交后同步计数与正文标记；全部卡片“定位原文”跳到收藏位置，“返回阅读”回到进入前阅读位置；全局返回阅读使用44px方形ChevronLeft图标，独立左上等上/左边距，桌面与标题同排；标题、说明、搜索、计数与列表共左线；全局主视图中阅读与知识贴不可交互。窄屏入口保持相同方形纯图标，搜索、失败重试与列表操作保持横向文字和可达热区。
5. 收藏回原文按实际文字范围定位：短范围中心对齐实际阅读可见区中心；整体放不下的长范围以首字行中心定位；每次相同，允许滚动边界自然夹限。该规则与普通知识贴/目录定位隔离。从全部收藏定位时，目标位置就绪前保持列表，阅读第一可见帧已定位，不展示旧位置再滚动；返回阅读仍恢复进入前位置。全部收藏左侧目录仍可交互，选择后退出收藏并按原章节规则跳转，正文和知识贴保持不可交互。
6. 缺图重试使用原位RotateCw纯图标与44px热区；loading禁重复，失败就地说明且能再试，读屏同步播报。独立空挂点控件不得加入正文文字节点或改变锚点。旧记录缺少安全原图地址时明确不可重试，不猜造地址。
7. 重生成当前展示页后核查桌面和窄屏；历史截图和评审保留原事实，不覆盖成新证据。
8. 展示页之外还要检查真实组件所在页面，包括上下文尺寸、加载与异常状态。

后续方向（未实施）：逐步用共享真实 React 组件生成样例，减少双份结构维护；不为了这一目标立即引入完整组件库或 Storybook。

## 8. 开发与验收清单

**修改前：** 阅读本文、相关实际组件、功能规格；确定复用的按钮类型与状态，最多列出几个关键风险。

**修改中：** 优先改共享规则；不新增随手写的主题色，不用大范围 `!important` 掩盖优先级冲突；必要例外写明场景。保留样式层 `reader-base → controls` 的关系。

**交付前：**

- [ ] 相关控件的默认、hover、按下、禁用可辨认；选中/焦点/展开按需补查。
- [ ] 键盘可到达并操作，禁用确实不可执行；纯图标有名称。
- [ ] 真实页面桌面与窄屏无挤压、裁切、溢出；必要时检查触控热区。
- [ ] 文案、图标、主次与危险层级一致；小字号在交互态也清晰。
- [ ] 同步受影响展示样例，截图注明版本、视口和模拟/真实范围。
- [ ] 按项目任务分级执行测试、独立审查与留证；普通文档维护不重复运行应用测试。

新增行为按 OpenSpec 流程；规范维护不绕过功能评审。对合理例外，记录原因、适用范围和验证证据，避免将一次特殊样式推广成全局规则。

## 中性纸面阅读排版（2026-10-19 修订）

MD/Web原文与译文使用#fbfbf8纸面、#232429思源衬线正文，桌面18px/1.75、≤560px17px/1.75。推荐外框720px含左右40px；≤1260px外框704px含左右32px；窄屏100%宽含左右24px。标题/段距沿用户选定原型。阅读区与知识贴采用reading-paper；共享paper、按钮和浮层同为中性纸面，桌面分区用reading-desk。PDF原页canvas与原位译文字体、颜色和布局保留。

## 简化阅读起始页（2026-10-19）

首页按已确认独立原型 V2 接入：唯一 h1 为“哪句不懂，划哪句”，副标题为“选中文字或框选 PDF，在原句旁直接提问、查证并留存”。中心为文件/链接共框导入、紧凑续读（有材料时）；底部为三张同时可见的功能卡片；不常驻展示完整材料列表或真实长知识贴。
